项目：多多买菜选品提效

围绕同一业务场景，从三个角度展开，分别验证三块能力（均为公开场景推演，指标为设计预期）

业务背景：多多买菜是拼多多社区团购业务，采销需在节庆/换季窗口前完成选品、招商、复盘。在此业务线从事运营约 1 年。

核心问题：一线两大痛点——选品依赖经验判断，复盘招商依赖手动操作。

解决方案：设计面向采销的选品提效工具，覆盖诊断、选品、招商、复盘四个环节，从设计、数据、评估三个角度展开。

角度一｜产品设计与落地（0→1 概念设计）

证明能力① · 产品设计与落地

这是什么 ▸ 面向多多买菜采销的节庆全周期选品 Agent：节前自动推品 / 节中实时监控 / 节后及时复盘

解决什么问题 ▸ 节庆选品依赖经验、手动排期 8h/周期；开卖后"让利还少卖"无人盯；复盘滞后、结论不沉淀到下个节庆

关键动作 ▸ 完成需求洞察 → PRD → 信息架构 → 技术选型；确立"以 Agent 为核心，重决策、轻操作"——Agent 出初稿，采销做终稿

满足什么需求 ▸ 一个 Agent 覆盖节庆全周期：采销不必从零操作，同时保留对口径与清单的完全掌控

0→1 全链路设计需求→PRD→架构选型方法论
+

面向社区团购采销、依附于内部系统的独立 Web 界面，按节庆周期分三段：节前自动推品 → 节中实时监控 → 节后及时复盘，由同一个 Agent 贯穿，将经验驱动选品转为数据驱动。从 0 到 1 完成产品全流程设计：需求洞察、PRD、信息架构、技术选型；其中"会自己动手查数"的智能核心由 tool-use Agent 实现。

背景与痛点

痛点现状影响
节庆换季无目标采销靠经验选品，无数据支撑招商品质不稳定
排期耗时长手动选品排期 8h/周期效率低，错过最佳招商窗口
招商困难采销逐一联系商家，回复率低招商转化率低，缺品严重
节中异常无人盯开卖后靠人工盯盘，降价是否换来销量无人判断"让利还少卖"的品持续亏损，等发现已过大半程

设计目标：选品排期从 8h 压缩至 3h 内，提升招商效率与采销采纳率。

目标用户与场景

  • 用户：社区团购采销（非技术岗，重效率、轻操作）
  • 核心场景：节庆/换季前的选品决策、商家招商、售后复盘

产品决策（PM 思考）

  • 不做全自动替代，采用"AI 生成 + 采销拍板"：采销保留对清单的增删和最终决策权，降低采纳门槛。
  • 用"45 天节庆提醒"把被动响应变主动，抢招商窗口。
  • 招商动作加"72h 冷却 + 15 天 3 次上限"护栏，避免骚扰商家、保护关系。

功能解决什么验收标准（设计预期）
品类助手-爆品推荐节庆换季无目标AI 自动生成招品清单，采纳率 >70%
45 天节庆提醒错过招商窗口节庆前 45 天自动提醒 + 跳转清单
一键招商招商效率低批量邀请，72h 冷却防重复，15 天最多 3 次
节中 ROI 监控让利还少卖没人盯双负品当日提醒，调盘建议采纳率 >60%
爆品复盘面板不知哪些品该换自动跑复盘，高销量/高转化品与滞销品主动推送

智能核心（tool-use Agent）：节日招商流（45 天提醒 → AI 生成招品清单 → 一键招商 → 商家响应 → 冷却策略 → 确认/替换）；节中监控（盯销量与 ROI，识别 ROI 双负即"让利还少卖"→ 提醒调盘）；节后复盘自动化（定时触发 → 拉数据 + 拉去年同期 → 算指标、识别高销量/高转化品 与 滞销品、打标签 → 结论存储 → 日报/周报/月报推送）。这一层由 tool-use Agent 实现，是工具背后"会自己动手查数"的能力。

节中 · 实时监控（销量 + ROI）

开卖期间的监控口径与处置动作。异常才打扰，无异常不推送。

监控项口径判定处置动作
销量销售件数日环比 / 对比预期异常波动（爆量或断崖）补货 / 上调售价控量
ROIGMV 变化率 / 收益率变化差值双负：GMV 变化率 与 收益率变化 同时为负调盘（调整售价） / 换品

关键设计：双负即"让利还少卖"——让出去的利润没换回销量，是最该被及时干预的信号。

预期效果（设计目标）

选品排期 8h→3h（↓62.5%）、商品上架 +12.5%、新品月均 GMV +8%、AI 推荐准确率目标 78%、采纳率目标 62%→72%+、任务发布使用率目标 25%→50%+。

复盘与迭代

  • 局限：概念设计阶段，未做真实用户可用性测试；准确率依赖底层数据质量。
  • 下一步：补充采销深度访谈验证采纳率假设；增强"自定义清单"的引导设计（在 AI 清单上采纳/剔除/替换），帮助采销养成自定义习惯，降低整单采纳门槛。

设计迭代记录（来自真实反馈）

第一版做成"纯 Agent 推送"：Agent 直接给终稿清单，采销只点确认。内部评审反馈——采销没有掌控感，不能改、不能挑，业务经验无处施展，不会用。

据此改为"Agent 出初稿，采销做终稿"：Agent 预填口径与清单，采销可逐条改、可剔除、可加回，终点仍是一键招商。掌控感回到采销，AI 不出"替人决策"的越界感。这一版才立得住。

比起一版到位的理想方案，被真实反馈推翻再收敛的过程，更能说明产品判断如何形成。

对标结论 · 分类判断：竞品多为"日常陪伴型"（常驻、全流程渗透）；本工具与扣子（Coze）同属"任务驱动型"——有节庆窗口才开、干完即关。这一定位决定使用模式与留存逻辑：不求常驻，求"关键时刻用得上、结果可信赖"。更贴近的真实对标是盒马/小象/朴朴的采销侧选品 AI，但多为内部系统不可见，故以牵牛花/京麦/Coze 为公开参照。

真实产品评测：扣子（Coze）

  • 业务价值：降低 Agent 搭建门槛，把开发从代码中释放。
  • 用户价值：任务驱动型（有活开、没活关），低门槛是留存关键；个人日均使用 1h+，门槛低带来高于同类的留存。
  • AI 质量：准确率较高、幻觉率低；响应 10s–1min 偏慢，说明任务驱动型对时延容忍度高于实时交易。
  • 可持续：无 novelty effect 风险；费用较高是门槛；AI 迭代快有替代风险。
  • 关键洞察：扣子的"任务驱动型"定位，正好印证本工具技术取舍——单 Agent + 工具调用足够，不必上多智能体（详见下节）。

技术认知与商业判断

同一场景，技术怎么选、风险怎么控、账怎么算

为什么是 RAG + Prompt，而不是微调 / 多智能体

方案适用前提本场景匹配度结论
微调 Fine-tuning规则隐式、无现成知识可检索、需模型内化领域能力低：口径/筛选条件是显式规则，数据日更、规则随节庆变，无稳定标注集不采用
多智能体 Multi-agent任务真正并行独立、需多方协商低：选品→监控→复盘是单用户单循环，一个 Agent 配工具调用就够，多体只增协调成本不采用
RAG + Prompt事实需引用实时/内部数据、规则可写清高：销售/库存/毛利来自内部接口实时查；规则用 Prompt 落地；历史复盘进 RAG采用

怎么控幻觉、保证可控

  • 数据只走授权来源：业务数字来自已授权的内部接口与历史复盘库，不联网现编；外部搜索热度走内部的高搜索趋势平台或授权数据，不爬第三方。
  • 每个数字带出处：结论可展开"依据"，点开能看到数字来自哪张表、哪个接口，方便核对。
  • 人做最后一道关：Agent 出初稿、采销做终稿；一键招商是确认点，调盘建议要采销拍板才执行，异常才提醒、不自动改价。

质量、成本、速度怎么权衡

  • 质量：RAG + Prompt + 带出处，达到"辅助决策"够用的准确度；工具是帮手不是替身，不追求零出错，追求说得清、能核对。
  • 成本：没有训练开销，只有接口调用与存储，低于微调和多智能体编排。
  • 速度：选品和复盘不是实时交易，节中监控按批跑即可；外部搜索热度走内部的高搜索趋势平台或授权数据，不爬，不卡单次请求。重点在节中双负早发现，减少"让利还少卖"的亏损。

真上线：数据从哪来、合规怎么处理

  • 数据来源：销售/库存/毛利/商家信息走内部接口（已在设计中）；历史复盘进 RAG；外部搜索热度走内部的高搜索趋势平台或授权数据，不爬。
  • 隐私合规：商家供价与信息属商业机密，内部权限隔离并脱敏；模型调用走不自留数据的接口或自部署，不进第三方训练；采销视角只读，不暴露 C 端用户隐私。

商业 & ROI 视角

  • 价值：选品排期 8h→3h（设计目标）；招商采纳率 >70%；节中双负早干预，减少"让利还少卖"的亏损。
  • ROI（设计预期测算）：人力节省 × 频次 + 减少的损耗，对比研发与推理成本。单采销每周期省 5h × 年 N 周期；双负品早干预 3 天可减少部分亏损。
  • 判断：对内工具看"省 + 赚"——省人力、降损耗，选品质量带动 GMV；不直接创收，但损耗与效率本身就是利润。

做了哪些取舍

  • 砍掉的：全自动替代采销（保留拍板）、多智能体、微调、硬实时、C 端个性化。
  • 保留的：单 Agent + 工具调用、结果带出处、人工兜底、异常才打扰。
