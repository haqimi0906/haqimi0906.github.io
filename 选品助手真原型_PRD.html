选品助手 · 真原型 PRD（作品集案例四）

定位：把《案例一｜AI 选品排期助手》从"概念设计"落地为真实可运行的 Agent 原型。 目标：补上作品集最缺的"我真搭过、跑通过"证据，作为面试最强谈资。 数据：使用公开/合成零售数据集，不涉及任何公司机密（数据隔离原则）。 ✅ 构建状态：原型已落地，mock 模式已验证可运行（见 agent_selection_prototype/demo_output.txt）。

1. 背景与目标

  • 问题：概念设计阶段的所有判断（8h→3h、采纳率 62% 等）都是预期值，缺乏真实构建与验证。面试官会追问"你真做过吗"。
  • 目标：用公开数据搭一个能跑的选品助手原型，验证核心 loop（中文提问 → 数据工具分析 → 诊断/推荐），并沉淀可演示 Demo + 产品文档。
  • 成功标准（设计预期）：用户用自然语言完成 1 次选品诊断或招品清单生成；输出可读、可解释；架构清晰可讲。

2. 目标用户与场景

  • 用户：电商/社区团购运营、采销（非技术，重效率）。
  • 场景：本工具按节庆周期分为三个阶段，由同一个 Agent 贯穿始终（节前 / 节中 / 节后）：
  • 节前 · 自动推品（前瞻选品）：节庆/换季前，采销选节日 → 系统出大商品池（本卖场缺、现存商家、同品供价最低、去年 GMV 前 30% 的节庆品）→ 剔除 → 自定义清单 → 一键招商。
  • 节中 · 实时监控：开卖期间盯销量与 ROI 两个指标；出现 ROI 双负时主动提醒调盘（调整售价），无异常不打扰。
    • ROI = GMV 变化率 / 收益率变化差值
    • 双负判定：GMV 变化率 < 0 且 收益率变化 < 0，即让利还少卖——让出去的利润没换回销量，需及时调整售价
  • 节后 · 及时复盘（向后看）：场次/周期结束后，自动跑复盘——生成高销量/高转化品清单、标出滞销品（支持一键标注）、预生成下节清单待确认，结论沉淀供下个节庆继承。
  • 界面形态：节前见 case1_ui_mockup.html（选节日 → 出池 → 剔除 → 招商，前瞻口径）；三阶段完整形态见 agent_console_draft.html。
  • 与概念设计的区别：概念设计只画了 PRD；真原型要让其中一个核心 loop 真正跑起来。

3. 核心功能（MVP 范围）

功能 说明 是否 MVP
品类健康度诊断 输入品类/周期，输出动销、毛利、退货、曝光转化诊断 ✅

4. Agent 架构

用户(中文问法)
   │
   ▼
[LLM 编排层] ── 理解意图 → 决定调用哪些工具 → 汇总成自然语言结论
   │
   ├── Tool: query_sales(品类, 周期)   → pandas/SQL 查公开数据集
   ├── Tool: diagnose(品类)            → 算动销/毛利/退货/转化，打标签
   ├── Tool: recommend(品类, 节庆)     → 按规则+历史输出招品清单
   └── Tool: find_anomalies(周期)      → 识别双负异常品
   │
   ▼
[记忆层] 会话上下文（记住用户当前品类/周期）
[护栏层] 口径校验（周期合法、品类存在）、无 key 时 mock 模式兜底
  • 为什么这样选型：沿用概念设计的"数据库答是什么、RAG 答为什么、规则用 Prompt"原则；真原型用函数工具（Tool）替代 RAG/API，降低依赖、保证可离线演示。

4.1 结构化 sheet 与 Agent 的关系（一个常见的设计误区）

界面里的"筛选条件 + 商品池 + 清单"是一套结构化数据工具——筛选、排序、口径校验这些能力，没有 AI 也成立。如果把产品做成"一堆筛选项"，AI 确实只是锦上添花。本工具的设计关键在于把 Agent 放在结构化工具之上作为 intelligence 层，让 AI 承担结构化工具做不了的三件事： 1. 意图转条件：采销用一句话（"帮我准备开学季、本卖场缺、供价有优势的节庆爆品"）即可生成清单，Agent 把自然语言解析为筛选条件组合，省去逐一手动配置。 2. 趋势解释：全国搜索量等字段不只是展示数字，Agent 结合行业语境说明"为什么涨、值不值得提前招商"，把数据变成判断。 3. 招商对话：一键招商背后的商家沟通、议价、跟进由 Agent 完成，结构化按钮只是入口。

即：结构化工具保证"查得准、算得对"，Agent 保证"说得清、用得顺、接得住后续动作"。两者分离但协作，这也是把"选区助手（NL 指令栏）"直接做在界面顶部的原因。 - 技术栈：Python + OpenAI 兼容 LLM 客户端（默认支持 DeepSeek/通义/OpenAI，环境变量切换）+ pandas 数据分析。无 key 时进入 mock 模式，仍可按预设逻辑演示。

5. 数据方案

  • 使用合成零售数据集（生成脚本产出 sample_data.csv）：含 品类 / 商品 / 周期 / GMV / 订单 / 毛利 / 退货率 / 曝光转化率 等字段，覆盖生鲜、日用、家电等类目与多周周期。
  • 理由：公开、可控、无合规风险，足以演示诊断与推荐逻辑；真实数据集（如 Olist）可作为二期替换。

6. 评估方案（eval）

  • 工具调用准确率：给定问题，Agent 是否调用了正确工具与参数。
  • 结论合理性：诊断/推荐是否符合数据事实（人工抽检 + 规则校验，如推荐品必须来自高动销低退货）。
  • 可解释性：每条结论是否附带数据依据。
  • 护栏：周期/品类非法输入是否被拦截；mock 与真实模式输出一致性。

7. 护栏与边界

  • 数据隔离：仅用合成/公开数据，绝不接入公司数据。
  • 不虚构：Demo 中的指标来自合成数据，明确标注，不暗示真实业务结果。
  • 范围声明：原型不连接真实商家/招商系统，招商与提醒为二期。

8. 复盘与迭代（构建后补）

  • 待补充：真实 LLM 联调后的准确率、遇到的最大技术/产品决策、下一步（接 RAG 历史报告、做定时调度、出 Web UI）。
